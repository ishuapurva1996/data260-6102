# Part 3 experiment

This extends the foundation's `web_application` package. It defines no replacement engine, model, auth dependency or base schema. Use `requirements.txt` in an isolated virtual environment. Run `.venv/bin/pytest`, not `python -m pytest` from the repository root, because the historical top-level `code` package shadows Python's standard library debugger module.

## Reproduce safely

1. Provision a **new dedicated MySQL 8.4 container**, separate volume, loopback host port, and database `s6102_rel`. Never point this experiment at a sibling's database. Keep `HW4_DATABASE_URL` and the three `HW4_SEED_*` account variables in ignored `.env` or an external private file. Export/load them using `python-dotenv` before setup commands. The shared HTTPS launcher accepts `--env-file`.
2. Apply the foundation migration and seed only an account: `python scripts/hw04/db_setup.py --migrate --through 1 --seed-account`. Do not seed demonstration rentals into the experiment database.
3. Create an ownership JSON **outside the repository** containing `format_version: 1`, `purpose: "hw04-part3-performance"`, `disposable: true`, `host`, `port`, `database: "s6102_rel"`, live `server_uuid`, complete `docker_container_id`, and `docker_container_name`. Read the UUID from `SELECT @@server_uuid`; confirm Docker's published port. The script independently checks these observations before writes.
4. Run `python scripts/hw04/part3/seed_data.py --ownership-manifest /private/tmp/hw4-part3-ownership.json --schema-revision 001_initial.sql --output reports/hw04/raw/part3/seed_manifest.json`. A nonempty rentals or managers table is refused. There is no reset, delete or drop option. The CLI reserves its evidence file before inserts and writes it before the transaction commits, so an invalid path or write failure cannot silently strand a successful seed. The live migration journal/checksums, all 5,000 six-field records, manager associations, and a generated-versus-stored checksum are checked.
5. Verify on the dedicated instance with `HW4_PART3_MYSQL_TESTS=1 HW4_PART3_OWNERSHIP=/private/tmp/hw4-part3-ownership.json .venv/bin/pytest tests/test_hw04_part3*.py -q` after loading the private environment. Tests temporarily change relationships inside an outer transaction that is rolled back. Ordinary unit tests run without the opt-in and skip the MySQL checks.
6. Coordinate exclusive port **8702** with Parts 1 and 2. Commit the executed source, start one process without reload using `python scripts/run_hw04_web.py --env-file .env`, and record the actual process, database, runtime versions and unchanged initial index state in a non-secret benchmark configuration JSON. Wait for any stress tests or database writes to finish.
7. Run `python scripts/hw04/part3/benchmark.py --config reports/hw04/raw/part3/benchmark_config.json --ca-file tmp/https/cert.pem --email-env HW4_SEED_EMAIL --password-env HW4_SEED_PASSWORD` with private credentials loaded into the environment. The local certificate is explicitly trusted for this client only. No tokens or passwords are put in output.
8. Select a successful complete attempt, then run `python scripts/hw04/part3/summarize.py --raw reports/hw04/raw/part3/attempts/<run-id>/requests.jsonl --output-dir reports/hw04/part3`. Preserve every earlier attempt; only the selected run belongs in the results table.
9. **After the benchmark**, run `python scripts/hw04/part3/index_experiment.py --ownership-manifest /private/tmp/hw4-part3-ownership.json --seed-manifest reports/hw04/raw/part3/seed_manifest.json --output-root reports/hw04/raw/part3/index-attempts`. It applies migration003 through the foundation runner and preserves EXPLAIN and index inventories. An existing title index is refused, never dropped to recreate an artificial before state.
10. Import the collection in `reports/hw04/part3/postman_collection.json` into real Postman and follow `reports/hw04/screenshots/part3/README.md`. Screenshots are separate functional evidence, not additional selected benchmark rows.

## Query and timing definitions

Both authenticated GET endpoints accept `page_size` from 1 through 200 and nonnegative `offset`; evidence uses 10, 50, 200 and offset 0. Both order by rental ID and return the foundation's seven ordinary fields plus `manager: {id,name}` or null. The naive endpoint always issues an explicit SELECT per rental, including repeated/null manager IDs. The fixed endpoint executes one left join. Neither adds artificial delay.

`X-SQL-Statements` counts actual SQLAlchemy cursor executions during that request, including the shared auth lookup and activity UPDATE. `X-Data-SQL-Statements` is a subset tagged on list/manager statements. A pure ASGI middleware starts the mutable request-local counter before dependencies and reads it after JSON serialization; copied thread contexts share only their own request's counter. Counters are returned only on these two experiment routes. DBAPI protocol operations such as connection setup, pool ping, BEGIN, COMMIT and ROLLBACK are outside the statement-event count; they still contribute to HTTP latency.

The runner authenticates, checks full naive/fixed response equality for all three sizes, and warms up three times per group. These requests are saved separately. It then makes exactly 30 requests for each size/version, serially in size order 10, 50, 200 and alternating naive then fixed. `perf_counter_ns` measures from HTTP GET start through complete response-body receipt, in milliseconds. JSON equality validation runs outside the timer after every response. Wrong status, count, payload or SQL headers aborts and preserves the failed attempt.

Percentiles use R7 linear interpolation at rank `(n-1)*p` in sorted observations. Speed-up is the naive percentile divided by the fixed version's corresponding percentile, not the percentile of paired ratios. At 30 samples, p95 and p99 remain sensitive to slow observations. No result is assumed before running.

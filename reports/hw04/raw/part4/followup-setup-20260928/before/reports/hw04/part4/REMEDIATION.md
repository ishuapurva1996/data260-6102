# Preserved unsuccessful attempts and bounded remediation

The first scored experiment is `reports/hw04/raw/part4/scored-20260928-01/`. All 22 authentic outputs remain unchanged. Its Qwen3 1.7B C answers refuse Q5 and Q6 exactly, but none of Q1–Q3 meets the complete supported-and-cited answer target. Q1 lacks retrieved deadline evidence. Q2 incorrectly assigns hazard detection to a paint inspection. Q3 omits available records/reports; its needed third chunk was dropped because the conservative UTF-8-byte bound reached 2,050 against the 1,800-token evidence budget. A Q3 and A Q4 reach the fixed 384-token output limit. These are observed failures, not replaced answers.

The development record is separate from the scored questions. `development-pilot-01` used the original concise C instructions. `development-pilot-02` tried longer general ambiguity and procedure-matching instructions. The longer prompt did not fix the wrong lawsuit/complaint deadline or ambiguous-case deadline and introduced an unsupported $1,000 deduction. The original concise prompt was selected and remains fixed.

One bounded remediation keeps the same five sources, chunking, embeddings, exact six questions, top-k settings, relevance cutoff 0.50, C rules, 4,096-token window, seed 6102, temperature zero and 384-token answer limit. It changes the generator to the public local Qwen3 4B and uses its pinned tokenizer to count evidence. All three configurations use the same replacement model; the complete 22-response comparison is repeated. This joint change does not isolate the causal effect of model size from token budgeting.

The first 4B development pilot exposed a serving-template issue: the downloaded Ollama template unconditionally ended with `<think>` even when `think:false` was supplied. The resulting answers were reasoning continuations that hit the output limit. `development-pilot-03-qwen4b` preserves those outputs. The official pinned Qwen tokenizer now applies its chat template with `enable_thinking=False`, and Ollama receives that full wire prompt with `raw:true`. This is the same empty-thinking template for A, B and C; A's user message is still exactly the question. The exact wire prompts are saved. No model answer is parsed into a replacement answer.

`development-pilot-04-qwen4b-raw` checks this correction on the eight separate development questions before the repeated scored run. Any surviving retrieval, ambiguity, citation or answer failure is retained and evaluated; no final-test answer key enters prompt construction or filtering.

The 4B runtime remained unsuitable even with the official no-thinking wire prompt. Pilot 04 was stopped with an explicit interruption receipt after retaining its generated reasoning continuations and saved requests. The final code removes that abandoned raw-template path. No 4B result is substituted into the selected matrix.

The selected repeat instead uses the original `qwen3:1.7b` digest with its working Ollama no-thinking template and its own pinned tokenizer. `development-pilot-05-qwen17b-tokenizer` produced eight finished development responses; all three unsupported questions were refused exactly. Actual prompt counts equaled the tokenizer text count plus 16 template tokens, within the 128-token reserve. The known complaint/lawsuit and ambiguous-case failures persisted.

The common output ceiling is raised from the proposed 384 to 768 tokens before the repeat freeze because the original no-RAG baseline hit 384 twice. Two separate baseline development calls in `development-answer-length-01` finished normally at 271 and 378 tokens under the new ceiling. All final configurations and sweep calls use 768, temperature zero, seed 6102 and the same 4,096-token window. This capacity adjustment is explicit; it is not a changed answer or a configuration-C-only advantage.

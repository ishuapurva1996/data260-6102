# AI use — Part 3

1. **What AI assisted with, and what the user supplied.** The user supplied the existing repository, correct HW3 baseline, assignment, implementation plan and shared contract. Codex implemented the Part 3 generator, ownership guard, two query strategies, request-local SQL instrumentation, benchmark/summarizer, index experiment, tests and evidence fragment. Bounded agents helped with separate modules and review. The shared backend came from the Part 2 session. This fragment does not claim the user manually wrote or independently tested these additions.
2. **One unsuitable output, and an independent check.** The initial seed CLI opened its evidence file after committing inserts; an invalid output directory could leave a seeded database without its manifest. Review found this and a regression test reproduced it. We checked whether the deliberately naive endpoint really executes one manager SELECT per rental when many rentals share the same manager. An ORM identity map can return an already loaded object, so a plausible-looking N+1 implementation can undercount the intended queries. We also checked that auth and session activity are included in total SQL.
3. **How it was checked.** The seed regression supplied a path whose parent was an ordinary preserved file and confirmed that the old CLI tried seeding before rejecting it. Tests used the real MySQL instance and the foundation's real auth dependency. A separate SQLAlchemy execution listener compared every executed statement with the response headers. Another test temporarily assigned repeated manager IDs and one null manager under a transaction, then rolled it back. Concurrent requests checked that counters did not leak between requests. Full payload equality, generated-versus-stored dataset hashes, and independently recomputed raw-data summaries provide additional checks.
4. **What changed and why it works.** The final seed CLI reserves an exclusive evidence file before inserts and writes it inside the transaction before commit; write failures therefore roll back inserts. New guard tests pass. The naive route uses explicit SELECT statements instead of `Session.get` or lazy relationship access. The fixed route materializes the same fields through one left join. A mutable request-local counter covers thread-pool dependencies and serialization. Review removed repeated dataset/baseline hashing while keeping the evidence checks. No timings, SQL counts or Postman images were invented. After the user made Postman available and helped install the custom public CA, Codex operated the real Postman UI to run the functional collection and capture six endpoint responses plus supporting headers/tests. A separate visual audit checked all 23 captures for readable evidence and exposed secrets. File-format verification then found that the native API had emitted JPEG bytes despite the chosen `.png` names. Codex retained every exact native JPEG and saved true PNG copies; the [format check](../raw/part3/postman/image-format-check.json) verified identical decoded pixels and dimensions, with no crop, resize, annotations or compositing. The [capture inventory](../screenshots/part3/README.md) now records 6/6 complete; these functional requests did not alter the selected 180-request timing dataset or its metrics.
